Test 1.1 — Clean-Speech Accuracylive data

How accurately the model transcribes clean, read English speech across eight standard benchmarks.

How this test works — what, how, dataset & metrics

What it measures

The baseline accuracy test. It plays clean English audio from well-known public corpora and compares the transcript to the reference, so you can place the model against published numbers.

How the code does it

eval/stt/accuracy.py streams each clip over gRPC, then scores it with eval.utils.score_pair: text is normalised with Whisper's EnglishTextNormalizer and WER/CER/MER are computed with jiwer (edit distance over words/characters). Per-dataset means are written to accuracy/summary.csv with a PASS/warn verdict.

Dataset

LibriSpeech (test-clean / test-other) ↗VoxPopuli (en) ↗GigaSpeech ↗SPGISpeech ↗TED-LIUM 3 ↗AMI (meetings) ↗Earnings-22 ↗

Metrics in this test

WER — Word Error Rate — the share of words wrong (substitutions + insertions + deletions) after text normalisation. Lower is better; 0% is perfect.

CER — Character Error Rate — like WER but per character. Used for Chinese/Japanese where word boundaries are ambiguous.

MER — Match Error Rate — errors as a fraction of the aligned length; a companion to WER that is bounded 0–1.

Test 1.2 — Batch Performancelive data

Batch throughput and latency — how fast the model transcribes, by clip length and under concurrent load.

How this test works — what, how, dataset & metrics

What it measures

A speed test (not accuracy). It measures how quickly audio is processed for short/medium/long clips and how latency holds up when many requests run at once.

How the code does it

eval/stt/performance.py times each gRPC call, computing RTF = elapsed ÷ audio-duration and RTFx = its inverse, bucketed by clip length. A concurrency sweep replays the workload at increasing parallelism and records P50/P99 latency and mean RTF per level (concurrency_summary.csv).

Dataset

LibriSpeech (length-bucketed clips) ↗

Metrics in this test

RTF — Real-Time Factor — processing time ÷ audio duration. Below 1.0 means faster than real time.

RTFx — Inverse RTF (audio ÷ processing). Higher is faster; RTFx 20 means 20× faster than real time.

Test 1.3 — Streaming Performancelive data

Streaming responsiveness — how quickly partial and final words arrive during live transcription.

How this test works — what, how, dataset & metrics

What it measures

Measures the live-dictation experience: how soon the first word appears, how long results take to finalise, how stable partial hypotheses are, and whether streaming hurts accuracy.

How the code does it

eval/stt/streaming.py drives StreamingRecognize and records time-to-first-word, finalisation latency, partial latency and a stability rate (how often partials survive unchanged), plus a batch-vs-stream WER comparison. Percentiles are stored as dicts in summary.csv. English-only by design.

Test 1.5 — Noise Robustnesslive data

Noise robustness — how accuracy degrades as background noise gets louder, across four noise types.

How this test works — what, how, dataset & metrics

What it measures

Mixes clean speech with real-world noise at controlled signal-to-noise ratios and tracks WER as conditions worsen — a stress test for noisy rooms, cafés, streets and babble.

How the code does it

eval/stt/noise_robustness.py adds MUSAN/DEMAND noise to LibriSpeech at set SNRs, transcribes, and scores WER per (noise_type, SNR). It also reports delta_rel, the relative WER increase versus the clean baseline (snr=∞).

How this test works — what, how, dataset & metrics

What it measures

Flat, robotic speech is unpleasant even when intelligible. This measures expressiveness: pitch movement, rhythmic variation, pausing and tempo.

How the code does it

eval/tts/prosody.py extracts reference-free prosody features: F0 mean/std/range (pitch dynamism), an acoustic nPVI approximation (rhythm), pause ratio and words-per-minute. Intrusive F0-vs-reference metrics are not computable for a fixed synthetic voice (see 2.4).
